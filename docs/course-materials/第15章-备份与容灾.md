# 第15章 备份与容灾

《Linux 系统管理与运维》课程讲义 · 深圳职业技术大学

## 15.1 核心概念

- **RTO 与 RPO**：RTO（恢复时间目标）指业务中断可容忍的最长时间；RPO（恢复点目标）指可容忍的最大数据丢失时长。两者共同决定容灾方案的档次与成本。
- **3-2-1 备份原则**：至少 3 份数据副本，存放在 2 种不同介质，其中 1 份放异地。防的是"备份和原始数据一起被删/被加密"。
- **备份三种方式**：全量（完整拷贝，恢复最快占用最大）、增量（只备上次备份后的变化，链条断一环全废）、差异（备上次全量后的变化，恢复只需全量+最新差异）。
- **容灾架构等级**：冷备（异地只放备份数据，恢复以天计）→ 温备（异地有环境需拉起，小时级）→ 热备/主备（异地实时同步随时接管，分钟级）→ 双活（两地同时服务，秒级切换，成本与复杂度最高）。

## 15.2 关键知识点

1. 备份策略设计从业务倒推：先定 RPO/RTO，再选方案。例如 RPO≤5 分钟意味着必须做连续日志归档（如 MySQL binlog 实时上传对象存储），仅靠每日全备做不到。
2. "备份成功"不等于"能恢复"：备份文件可能损坏、脚本可能漏目录、恢复步骤可能没人会做。唯一的验证方式是定期真实恢复演练。
3. 备份必须监控：备份任务失败告警、备份文件大小突变告警（比昨天小 50% 大概率出了问题）、备份时长超限告警。
4. 数据库与文件备份分开设计：数据库用专用工具保证一致性（见第11章），直接 cp 数据目录得到的很可能是不一致的废文件；文件类用 rsync/restic 做增量去重。
5. 防勒索设计：备份存储与生产环境隔离权限体系，启用对象存储版本控制或 WORM（写入后不可改）策略，攻击者拿到生产权限也删不掉备份。
6. 容灾切换的最难点不是技术是决策：谁有权拍板切换、判断标准是什么（如主机房不可用超过 X 分钟）必须提前写进预案，临时开会讨论会把 RTO 拖到不可接受。
7. 演练指标化：每季度容灾演练记录实际 RTO/RPO 并与目标对比，不达标立项整改。

## 15.3 常用工具与技术栈

| 工具 | 用途 |
|------|------|
| restic / BorgBackup | 加密、去重的现代文件备份工具 |
| rsync | 增量文件同步的基础工具 |
| 对象存储（S3/OSS）+ 生命周期 | 异地备份仓库，自动转冷归档 |
| Velero | Kubernetes 集群资源与卷备份 |

## 15.4 典型实践场景与最佳实践

### 场景一：中小系统的务实备份方案
数据库每日凌晨全备 + binlog 每 5 分钟增量上传对象存储（RPO=5 分钟）；备份保留策略 7 天日备 + 4 周周备 + 12 月月备；每月抽一次备份在隔离环境做恢复演练并校验行数。

### 场景二：机房级故障切换演练
半年一次把生产流量真实切到备机房运行 2 小时：提前降 DNS TTL（见第12章）、按预案顺序切数据库主从与流量入口、记录每步耗时。首次演练暴露的问题（配置缺失、权限不通）正是容灾体系最有价值的产出。
