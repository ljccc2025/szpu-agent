# 第12章 网络运维

《Linux 系统管理与运维》课程讲义 · 深圳职业技术大学

## 12.1 核心概念

- **TCP 三次握手与四次挥手**：SYN → SYN+ACK → ACK 建立连接；挥手后主动关闭方进入 TIME_WAIT（约 60 秒），高并发短连接场景会堆积大量 TIME_WAIT。
- **DNS 解析链路**：浏览器缓存 → 系统 hosts → 本地 DNS（运营商/内网）→ 根/顶级/权威域名服务器逐级递归；TTL 决定记录缓存时长，也决定切换生效速度。
- **四层与七层负载均衡**：四层（LVS、云 SLB）基于 IP+端口转发，性能极高但不理解应用协议；七层（Nginx、HAProxy）能按域名、路径、Header 路由（Nginx 配置详见第5章）。
- **带宽与延迟**：带宽是管道粗细，延迟是路程时间；跨地域专线延迟受物理距离限制（北京到深圳光纤单程约 15ms），不是扩带宽能解决的。

## 12.2 关键知识点

1. 网络排查命令阶梯：`ping`（连通性与丢包）→ `traceroute/mtr`（逐跳定位断点）→ `ss -tlnp`（端口监听与连接状态）→ `tcpdump`（抓包终审）。mtr 长时间运行可发现间歇性丢包。
2. tcpdump 基本用法：`tcpdump -i eth0 host 10.0.0.5 and port 3306 -w out.pcap` 抓指定主机端口流量存文件，用 Wireshark 分析重传、RST、握手失败。
3. 连接被拒与超时的区别：Connection refused 表示对端明确回了 RST（端口没监听/防火墙 REJECT）；Timeout 表示包被丢弃（防火墙 DROP、路由不通、对端宕机），排查方向完全不同。
4. conntrack 表满：Linux 做 NAT 时每条连接占一条 conntrack 记录，表满后新连接静默丢弃，日志出现 `nf_conntrack: table full`，需调大 `net.netfilter.nf_conntrack_max`。
5. 内核网络参数三件套：`somaxconn`（accept 队列长度，突发流量场景调大）、`tcp_tw_reuse`（复用 TIME_WAIT 连接）、`ip_local_port_range`（客户端可用端口范围，影响对外连接数上限）。
6. MTU 与分片：默认 1500 字节，隧道/VPN 场景外层封装占用字节导致"ping 通但大包传输卡死"，用 `ping -M do -s 1472 目标` 探测路径 MTU。
7. 跨机房容灾网络设计：DNS 智能解析按地域分流 + 健康检查自动摘除故障入口，TTL 建议 60~300 秒以平衡切换速度与解析压力。

## 12.3 常用工具与技术栈

| 工具 | 用途 |
|------|------|
| mtr | ping+traceroute 合体，定位逐跳丢包 |
| tcpdump + Wireshark | 抓包与图形化协议分析 |
| ss / iproute2 | 连接状态、路由、网卡配置现代工具集 |
| iperf3 | 两点间带宽与丢包压测 |

## 12.4 典型实践场景与最佳实践

### 场景一：接口偶发超时五步定位
① mtr 双向各跑 10 分钟看链路丢包 → ② ss 查服务端 accept 队列溢出计数 → ③ 查 conntrack 是否满 → ④ 两端同时 tcpdump 比对（包在哪一侧消失）→ ⑤ 结合第6章监控看超时时刻的 CPU 软中断与带宽是否打满。

### 场景二：DNS 切换预案
域名切换前 24 小时先把 TTL 从 3600 降到 60，切换后观察新入口流量占比爬升，确认稳定后再把 TTL 调回，避免"改了解析半天不生效"。
