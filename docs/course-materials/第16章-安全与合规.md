# 第16章 安全与合规

《Linux 系统管理与运维》课程讲义 · 深圳职业技术大学

## 16.1 核心概念

- **最小权限原则**：任何账号、服务、进程只授予完成其职责所需的最小权限；权限应随职责变化及时回收，杜绝"离职半年账号还能登录"。
- **纵深防御**：不依赖单一防线，网络边界（防火墙）、主机（基线加固）、应用（输入校验）、数据（加密脱敏）层层设防，任何一层被突破仍有下一层兜底。
- **安全基线**：操作系统与中间件的标准化安全配置集合（如 SSH 禁止 root 登录、密码复杂度、日志审计开启），新机器交付即达标。
- **等级保护（等保 2.0）**：我国网络安全法定要求，按系统重要性定级（多数业务系统为二级或三级），三级系统每年需通过测评。

## 16.2 关键知识点

1. SSH 加固清单：改默认 22 端口、禁用密码改用密钥登录、禁止 root 直接登录、fail2ban 自动封禁爆破 IP、登录接入堡垒机统一审计。
2. 漏洞管理闭环：资产清单（先知道自己有什么）→ 定期扫描 → 按 CVSS 评分与实际暴露面定优先级 → 高危 7 天内修复 → 复扫验证。修不了的（如老系统）用 WAF 规则或网络隔离做缓解。
3. 补丁策略：安全补丁走"测试环境验证 → 灰度一批 → 全量"流程；内核补丁需重启的安排在变更窗口，紧急漏洞（如被公开利用的 RCE）走应急通道当天处理。
4. 密钥与凭据安全：禁止密码硬编码进代码与配置文件（管理方案见第9章 Vault）；凭据泄露应急三步——立即吊销轮换、排查使用记录、检查是否已被利用。
5. 堡垒机与审计：生产服务器只允许从堡垒机登录，所有操作留存可回放的审计记录；数据库高危操作（DROP、全表 UPDATE）需审批后经审计代理执行。
6. 数据安全分级：按敏感度对数据分级（公开/内部/敏感/机密），敏感数据存储加密、传输走 TLS、日志与工单中脱敏展示（配合第7章日志脱敏）。
7. 应急响应中的安全事件：疑似入侵时先隔离（断网保留现场）不要直接关机（内存证据会丢失），保存登录记录、进程列表、网络连接快照后再清理。

## 16.3 常用工具与技术栈

| 工具 | 用途 |
|------|------|
| fail2ban | SSH 等服务爆破自动封禁 |
| Trivy | 镜像与依赖漏洞扫描，可嵌入 CI |
| OpenSCAP | 基线合规自动化检查 |
| JumpServer | 开源堡垒机，登录审计与录像 |
| WAF（如 ModSecurity） | Web 攻击拦截与虚拟补丁 |

## 16.4 典型实践场景与最佳实践

### 场景一：新服务器交付安全基线
用 Ansible 加固角色（见第9章）统一执行：SSH 加固、关闭无用服务与端口、部署审计与 HIDS agent、接入堡垒机，最后跑 OpenSCAP 出合规报告，不达标不交付。

### 场景二：一次高危漏洞应急
某中间件曝出 RCE 漏洞且 PoC 公开 → 2 小时内用资产清单锁定 37 台受影响主机 → 无法立即升级的先下 WAF 虚拟补丁并做网络隔离 → 48 小时内完成灰度升级 → 复扫确认清零并出报告。
