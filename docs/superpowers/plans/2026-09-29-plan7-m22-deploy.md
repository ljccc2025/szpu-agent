# M22 部署与答辩演示 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** `docker compose up -d` 一键拉起全套服务，并配一份固定的六步演示脚本，让答辩现场零翻车。

**架构：** 多阶段构建把「装依赖 + 下模型」和「运行」分开——builder 阶段产出 `~/.local` 与模型缓存，runtime 阶段只复制产物，不带编译工具链。数据走卷挂载而非打进镜像，镜像可随时重建而错题本不丢。

**技术栈：** Docker 26.1.3、Compose v2.27.0、`python:3.11-slim` 基础镜像、多阶段构建、healthcheck、卷挂载。

## 目标环境实测（2026-09-29，动手前先探）

| 项 | 实测值 | 对方案的影响 |
| --- | --- | --- |
| 磁盘 | 48G 总 / 25G 空闲 | 够用。另有 **18 个无用镜像占 6.587GB（100% 可回收）**，收尾时清理 |
| Docker | 26.1.3 + Compose v2.27.0 | 满足 |
| 基础镜像 | **`python:3.11-slim` 已在本地缓存（133MB）** | 构建不依赖拉取，规避了镜像源不稳的风险 |
| **`pypi.org`** | **不可达（curl 失败）** | **构建必须指定清华镜像源，否则 pip 直接卡死** |
| `pypi.tuna.tsinghua.edu.cn` | 可达 | 作为 `PIP_INDEX_URL` |
| `hf-mirror.com` | 可达 | 构建期预热 bge 模型 |
| Docker registry | daemon 已配 `docker.1panel.live` 等镜像，但实测拉取会反复重试 | 更加确认「不要在构建期拉新基础镜像」 |
| docker 组 GID | **987**，socket 为 `srw-rw---- root:docker` | 容器内用非 root 用户 + `group_add: ["987"]` 即可访问 socket |
| 8000 端口 | 被现有 uvicorn 占用（有真实数据在跑） | **容器先映射到 8001 并行验证，不动现有服务** |
| `data/` | 1.9MB（chroma 向量库 + tutor.db 错题本） | 卷挂载，先备份再挂 |

## 设计决策记录

| 冲突 / 待定 | 本计划采用 | 理由 |
| --- | --- | --- |
| 端口 | **先 8001 并行，验证通过再议切换** | 现有 8000 服务带着真实数据在跑；镜像万一有问题不能连累它 |
| 沙箱怎么在容器里工作 | **挂载 `/var/run/docker.sock`（DooD）** | M11 沙箱要起容器。这是**真实的安全降级**：容器内进程等价于宿主 root（可挂载宿主任意目录）。教学项目取舍，在文档与 compose 注释中明写，不隐藏 |
| 容器内用户 | **非 root（`app`）+ `group_add: ["987"]`** | 虽然挂了 socket 已是 root 等价，仍按最小权限收敛其余面；GID 放在 compose 而非烘进镜像，换主机只改一行 |
| 模型 | **构建期烘焙进镜像** | 答辩现场断网也能起。代价是镜像大约 1.2–1.5GB，换「零翻车」值得 |
| pip 源 | **清华镜像，写死在 Dockerfile** | `pypi.org` 在目标机不可达，不写死构建必挂 |
| torch | **先单独装 CPU 版** | 否则 `sentence-transformers` 会拉 2.5GB CUDA 包 |
| 依赖来源 | **只装 `requirements.txt`** | M21 已拆分出 `requirements-dev.txt`，生产镜像不带测试工具 |
| `data/` | **卷挂载宿主目录，不进镜像** | 镜像可重建，错题本与向量库不能丢 |
| `.env` | **compose `env_file` 注入，不进镜像** | API Key 绝不烘进镜像层 |

## 验收标准

1. 在干净状态下 `docker compose up -d` 一条命令拉起服务，healthcheck 转为 healthy。
2. 容器内 RAG 问答带真实出处，证明模型已烘焙、向量库卷挂载正确。
3. 容器内沙箱能真实执行 Linux 命令并返回结果（DooD 生效）。
4. 六步演示全链路在容器上跑通，且 SSE 流式输出正常。
5. 全程不影响宿主原有的 8000 服务。
6. 交付后磁盘净增可控，并清理掉悬空镜像层。
