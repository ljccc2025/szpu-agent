# M15 SSE 流式输出 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 新增 `POST /api/chat/stream`，把 Agent 的回答逐 token 推给前端，并把工具调用过程实时可视化（`token` / `tool_start` / `tool_end` / `done`）。

**架构：** 四层各司其职，每层都能脱离上一层单独测试——① `ToolCallAccumulator` 纯逻辑还原流式分片的工具调用；② `LLMClient.stream()` 只负责把 SDK 的 chunk 转成统一 delta；③ `Agent.chat_stream()` 复用非流式那套「5 轮熔断 + 出处去重 + 落库」纪律，只是把结果改成逐事件 yield；④ `app/stream.py` 只做 SSE 文本封装。

**技术栈：** `fastapi` StreamingResponse、`openai` SDK v3（`stream=True`）、`pytest`、原生 JS `fetch` + `ReadableStream`。

| 是否替换 `/api/chat` | 未明确 | **并存，不替换** | `apitest.sh` 与 `tests/test_api.py` 都依赖非流式端点；流式只是新增能力，破坏性替换会砍掉现有回归网 |
| 前端技术 | 「前端 EventSource」 | **`fetch` + `ReadableStream`** | `EventSource` 只支持 GET，而本接口要 POST 会话体；`fetch` 流式读取是官方推荐的 POST-SSE 方案 |
| 异步还是同步生成器 | 「async generator」 | **同步生成器 + StreamingResponse** | `LLMClient` 用的是 openai 同步客户端；FastAPI 会把同步生成器放进线程池，行为正确且不引入 `asyncio` 心智负担（对应非功能需求「答辩每行代码都能讲清楚」） |
| 出处怎么传 | 未明确 | **随 `done` 事件一次性返回** | 出处卡是整体渲染的，逐条推没有收益；且与 `/api/chat` 的返回结构保持一致 |
| 工具参数是否推给前端 | 未明确 | **只推工具名，不推参数** | 参数可能含检索原文或学生答案；前端只需要显示「正在执行 rag_search…」 |

## 流式 Function Calling 的核心难点

非流式下 `msg.tool_calls` 是一次性拿到的完整结构；开 `stream=True` 后，同一个工具调用会被拆成多个 chunk：

```text
chunk1: delta.tool_calls=[{index:0, id:"call_x", function:{name:"rag_search", arguments:""}}]
chunk2: delta.tool_calls=[{index:0, function:{arguments:"{\"qu"}}]
chunk3: delta.tool_calls=[{index:0, function:{arguments:"ery\":\"nginx\"}"}}]
```

必须**按 `index` 分桶累积**：`id` 与 `name` 取首次出现的值，`arguments` 字符串逐段拼接。并发多工具时 `index` 0/1/2 各自独立，拼错就会串号。这部分抽成 `ToolCallAccumulator` 纯类，不碰网络，直接单测。

## 事件协议

| 事件 | data 结构 | 时机 |
| --- | --- | --- |
| `token` | `{"text": "片段"}` | 模型每吐出一段正文 |
| `tool_start` | `{"name": "rag_search"}` | 某个工具即将执行 |
| `tool_end` | `{"name": "rag_search", "ok": true}` | 该工具执行完毕 |
| `done` | `{"reply": "全文", "sources": [...]}` | 本轮结束，前端据此渲染出处卡 |
| `error` | `{"message": "服务暂时繁忙，请稍后再试。"}` | 异常兜底，前端显示错误气泡 |

SSE 载荷一律 `json.dumps(..., ensure_ascii=False)`：JSON 编码会把换行转义成 `\n` 字面量，天然避免裸换行破坏 SSE 帧结构。

## 验收标准

1. `curl -N -X POST http://127.0.0.1:8000/api/chat/stream` 能看到逐帧 `event: token`，而不是一次性返回。
2. 触发工具的提问（如「算一下 (2+3)*7」）能看到 `tool_start` / `tool_end` 帧。
3. 浏览器里回答是打字机式逐字出现，工具执行有独立气泡提示。
4. 原 `/api/chat` 行为不变，既有测试全部保持通过。
5. LLM 不可用时前端收到 `error` 帧并显示友好文案，用户提问仍已落库。
